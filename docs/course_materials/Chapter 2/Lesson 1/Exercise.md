# Transform Ad-Hoc Prompting into Documented Workflows

Identify three recurring development tasks and transform each into a documented, reusable AI-assisted workflow.

What to do:

 1. Identify three patterns: Think about your recent development work (or use TundraBoard as context). Identify three tasks you perform regularly that could benefit from a structured AI workflow. At least one should involve code generation and at least one should involve code review or analysis.

2. Document each workflow: For each task, create a complete workflow document using the structured format from the lesson:
    - Trigger: When does this workflow apply?
    - Prerequisites/Context: What information does the AI need?
    - Prompt sequence: The specific prompts (with placeholders for variable content), which tool slot to use, and which prompt pattern (CoT, few-shot, role-setting)
    - Verification checklist: How to confirm the output is correct

3. Test one workflow: Pick the most useful of your three workflows and actually run through it with a real (or realistic) task on the TundraBoard project. Document what happened — did the workflow produce good results? What would you change?

4. Reflect: Compare the workflow approach to how you would have done the same task ad-hoc. What are the concrete benefits? What are the trade-offs?

Submit: Three complete workflow documents, the results of testing one workflow, and your reflection on the benefits and trade-offs.

Stretch goal for experienced developers: Critique the four-component workflow structure itself. Is it sufficient for your context? Propose one improvement (e.g., a "failure mode" section, version history, ownership) and justify why it matters.
